3. Détail des corrections

Point 1 — Nouvelle commande

Cause : OrderTrackingScreen naviguait vers HomeTab → screen: 'Home', mais après le refactor Drawer l'écran Home est nested sous HomeMain → HomeStack.

Correctif : navigateToFreshHome(navigation) : - Navigue vers HomeTab → HomeMain → Home avec { reset: timestamp } - Remet à zéro la stack CartTab (évite OrderTracking stale) - Aucune logique métier — documenté comme utilitaire réutilisable

Point 2 — Annulation client

Mobile : - confirmAction() remplace Alert.alert (web + native) - showCancel = active && canCancelOrder(order.status) — source unique, plus d'état stale - onMissionStatus met à jour cancellable systématiquement - Post-annulation : navigateToFreshHome() — retour état normal - Bouton « Nouvelle commande » aussi visible après annulation

Backend (cancelOrderByClient — enrichissement post-transaction uniquement) : - SELECT offered_to_driver_id - clearOfferTimeout(mission_id) avant transaction - Mission UPDATE : NULL driver_id, offered_to_driver_id, offer_expires_at - mission:cancelled vers livreur assigné et livreur en offre - assignPendingOrdersToDriver() pour chaque livreur libéré

Driver mobile : - mission:cancelled clear activeMission et pendingOffer

4. navigateToFreshHome — contrat de l'utilitaire

Responsabilité unique : ramener l'app client à un état d'accueil propre.
Entrée  : navigation (n'importe quel écran client)
Sortie  : HomeTab actif, Home reset, CartTab stack = [Cart]
Interdit: logique commande, panier, mission, socket

Réutilisable depuis tout écran client sans effet de bord métier.

T8 tryDispatchNewOrder post-cancel ✅ offre émise

1. Verdict

Le cœur reste le Story/State Engine (Event → état → ConditionExpr → Actions). Simulateur et Test Terrain ne sont que deux sources d’événements vers le même handleEvent(). Aucune logique if (lantern === Magellan).

Cursor / Code → Lantern Engine → Lantern Lab → Dev Build / Internal Preview → téléphones de test → test réel Paris → journal → correction → validation → seulement ensuite App Store / Google Play

Existant réutilisable : QR partiel (Event Engine), journaux/idempotence backend, Lab sandbox admin.

Absent aujourd’hui : organe Lantern Engine, expo-location, NFC, audio/push, EAS preview builds, API iOS physique fiable (127.0.0.1 hardcodé).

2. Architecture globale

Sources événements ├── Lab Simulateur (source: lab_sim / forced) ├── Mobile Preview (source: mobile — GPS, QR, NFC réels) └── Scheduler serveur (time.schedule, schedule.after) ▼ EventIngest (idempotent, clientEventId) ▼ StoryStateEngine.handleEvent ▼ lantern_journal + trace debug ▼ ActionPlan → mobile Atelier ▼ Stream SSE/WS → Lantern Lab (Test Terrain live)

6. GPS réel & stabilisation

Zones : cercle, polygone, arrondissement, zone personnalisée. Trigger geo.enter / geo.exit / geo.heartbeat. Condition geo.inAnyZone.

Module serveur geoStabilizer : précision minimale, hysteresis enter/exit, debounce, cooldown, minDwellMs, confirmation de présence. Le client envoie { lat, lng, accuracy, at, clientEventId } ; le serveur décide enter/exit — évite ENTER/EXIT/ENTER en quelques secondes sur une frontière.

7. QR & NFC

QR / NFC = identifiants de balise logique (QR_MAGELLAN_001, NFC_MAGELLAN_001), pas la logique de l’aventure. Scan → Event → Rules.

Beacon catalogue dans Definition. Token opaque (esprit Identity). NFC iOS limité → fallback QR obligatoire sur même Beacon.

10. Golden Test #2 — Appel 20h17

Trigger temporel · zone « Bureau » · heure 20h17 · occurrence unique · missPolicy: expire → absent = appel perdu définitivement. Récurrent = prochaine occurrence. Actions : device.ringPhone → media.play → var.set.

11. Idempotence & offline

Chaque event client porte clientEventId UUID + Idempotency-Key. Retry réseau ne doit pas déclencher deux fois un talkie « once ».

Outbox device (offline)Serveur obligatoire
GPS samples, scans QR/NFC bruts, media.opened UI unlock média critique, Wallet, miss définitif, once exclusive, vars équipe

Sync → ingest idempotent → moteur. Conflit : serveur gagne. Miss 20h17 unique décidé côté serveur à l’heure due — sync tardive ne rattrape pas.

12. Match multi-Rules

  • Défaut : matchPolicy: 'all' — toutes les Rules candidates vraies s’exécutent (priority desc).
  • Groupes exclusifs : exclusiveGroupId — une seule Rule gagne dans le groupe.
  • Magellan : 3 Rules, même groupe exclusif, zones disjointes.

13. États médias & actions

Conserver DISCOVERED ≠ OPENED ≠ CONSUMED. Source de triggers (ex. media.consumed → +17 min → ring).

Actions critical vs non-critical : échec notification secondaire ne bloque pas l’aventure ; erreur journalisée avec Action id.

14. Versioning

Publish = snapshot immuable. Runs en cours restent pinés sur leur contentVersion. Correction → V5 ; nouveaux runs V5, anciens V4 jusqu’à terme.

20. Garantie : un seul moteur

  1. Un seul package backend/src/lib/lanternEngine.
  2. API simulate et POST mobile appellent le même handleEvent.
  3. Tests : même fixture Magellan via event synthétique et event mobile → traces égales.
  4. UI Lab n’évalue jamais les conditions en local — affiche la trace serveur.
  5. FORCER event = source: forced, interdit sur channel production.
LanternLab ──simulate/watch──► API_lanterns MobilePreview ──POST events──► API_lanterns API ──► StoryStateEngine.handleEvent API ◄── trace + ActionPlan LanternLab ◄── journal stream (SSE/WS) MobilePreview ◄── ActionPlan → Atelier UI

21. Critère de réussite

Créer Magellan + Appel 20h17 uniquement en données. Les valider via : (1) simulateur (2) téléphone (3) GPS réel (4) QR (5) NFC (6) heure réelle (7) heure simulée — sans modifier le code du moteur entre les deux aventures.

Le Lantern Lab = outil de création ARG. Le Simulateur = laboratoire virtuel. Le Test Terrain = laboratoire réel. Paris = environnement de test — avant publication publique.

Prochaine étape après validation : E0 uniquement (organe + fixtures golden en tests) — pas de rewrite mobile massif.

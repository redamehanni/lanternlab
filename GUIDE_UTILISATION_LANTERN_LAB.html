1. Qu’est-ce que le Lantern Lab ?

Le Lantern Lab est l’atelier du créateur pour construire des aventures ARG (Alternate Reality Game) appelées Lanternes dans Ma Zone.

  • Lantern Engine = le cerveau (règles, conditions, actions, temps, géo). Vous n’avez pas à le programmer.
  • Lantern Lab = l’atelier (étages, situations, langage humain). Vous concevez ici.
  • Simulateur S1 = laboratoire virtuel pour exécuter le vrai moteur avec une trace technique.
Vous (concepteur) │ pensez : ÉTAGE → SITUATION → SI / ET / OU → ALORS → TRANSITION ▼ Lantern Lab (interface) │ compile / traduit ▼ Lantern Engine (moteur existant) │ évalue ▼ Résultat joueur (messages, médias, sonneries, étages débloqués…)
Règle d’or. Vous ne devez jamais avoir besoin d’écrire geo.inZone, var.set ou du JSON pour créer une situation. Si vous voyez ce langage, passez en Mode Développeur uniquement pour diagnostiquer — puis revenez en Mode Créateur.

4. Les concepts fondamentaux

Maîtrisez ces quatre idées — tout le reste en découle.

4.1 Aventure (Lanterne)

Une aventure est un conteneur : titre, fuseau horaire, médias, lieux, balises, variables, et une liste d’étages.

4.2 Étage de situation

Un étage est une étape logique / narrative de progression (pas une « page »).

  • Numéroté : 0, 1, 2, … N
  • Peut contenir plusieurs situations simultanées (A, B, C…)
  • Peut définir une condition de passage vers l’étage suivant

Exemple Mira — Étage 1 « Premiers indices » : A lettre · B clé USB · C polaroid.

4.3 Situation

Une situation = un événement narratif identifiable, construit ainsi :

QUAND (déclencheur — ce qui vient d’arriver) SI (conditions — ET / OU / PAS) ALORS (actions — ce que l’app fait) SINON (actions alternatives — optionnel) TRANSITION (débloquer un autre étage — optionnel)

4.4 Les quatre niveaux à distinguer

ConceptQuestionExemple
SituationQue se passe-t-il ?« Le joueur consomme la lettre »
ConditionSous quelles exigences ?« Il est dans Rue de Paradis »
ActionQue fait l’application ?« Afficher un message »
TransitionEst-ce qu’on progresse ?« DONC étage 2 accessible »
Toutes les situations ne débloquent pas un nouvel étage. Beaucoup ne font qu’afficher un texte, changer un état, ou préparer une condition future. C’est normal.

5. Les trois vues : Liste, Arbre, Parcours

Important : Liste, Arbre et Parcours montrent les mêmes données. Modifier une situation dans l’éditeur met à jour les trois vues après compilation.

5.1 Vue Liste (recommandée pour concevoir)

Liste verticale d’étages dépliables.

  1. Cliquez l’en-tête d’un étage pour le déplier / replier.
  2. Cliquez une situation A/B/C pour la sélectionner → panneau Éditer à droite.
  3. Sous l’étage, la boîte pointillée 🔗 Condition pour l’étage suivant montre (ou propose) la transition.

Vous y lisez immédiatement :

  • QUAND …
  • SI / ET …
  • ALORS / PUIS …
  • SINON …

5.2 Vue Arbre

Cartes reliées par des étiquettes SI ALORS PUIS DONC.

  • Utile pour voir les convergences (plusieurs situations → même étage suivant).
  • Cliquez une carte situation pour l’éditer.
  • Les actions sont des cartes en pointillés (aperçu).

5.3 Vue Parcours

Lecture « côté joueur » : suite d’étages avec mentions de choix (A/B) et statut.

  • ✓ conception / atteignable
  • 🔵 ouvert (pendant une session Parcours active)
  • ⚠️ inatteignable (selon les validations)

Utilisez cette vue pour vérifier que le chemin imaginé correspond au chemin réel.

7. Créer une aventure de zéro

  1. Cliquez + Nouvelle aventure (colonne gauche). Un étage 0 vide apparaît.
  2. Renommez l’aventure plus tard en sauvant un brouillon (le titre est dans les données ; pour Mira, le titre est déjà « Lanterne de Mira »).
  3. Préparez le matériel narratif (médias, lieux, balises) — aujourd’hui souvent via la fixture Mira ou en partant d’une copie brouillon. Sans médias/zones dans l’aventure, certains menus de sélection seront vides.
  4. Ajoutez des étages avec + Étage.
  5. Dans chaque étage, ajoutez des situations avec + Situation.
  6. Éditez chaque situation (section 8), puis les transitions (section 10).
  7. Cliquez ✓ Valider, corrigez les alertes, Compiler, Tester, puis Sauver brouillon.
Astuce pédagogique. Pour apprendre, chargez d’abord Lanterne de Mira, explorez les 15 étages, puis créez une mini-aventure à 3 étages avant de viser une ARG complète.

8. Éditer une situation — panneau par panneau

Sélectionnez une situation → onglet Éditer.

8.1 Titre

Nom humain de la situation (« Lettre consommée », « Code PIZZA correct »…). Les lettres A/B/C sont automatiques dans l’étage.

8.2 QUAND (déclencheur)

Ce qui vient de se produire pour que la règle écoute.

  1. Choisissez le type dans le menu (ex. « Le joueur consomme »).
  2. Remplissez les champs affichés (item média, balise, code, etc.).

Sans QUAND cohérent, la situation ne se déclenchera jamais au test.

8.3 SI / ET / OU (conditions)

  • + Condition (ET) : ajoute une exigence supplémentaire (toutes doivent être vraies).
  • + Groupe OU : crée un groupe « (A OU B) », combinable avec d’autres ET.
  • Bouton × : retire une condition.

Exemples de logique supportée :

  • SI A ET B ET C
  • SI A OU B
  • SI A ET (B OU C)

8.4 ALORS / PUIS (actions)

  1. Cliquez + Action.
  2. Choisissez le type (message, débloquer média, journal, sonnerie…).
  3. Remplissez les champs.
  4. Ajoutez d’autres actions : elles s’enchaînent (ALORS puis PUIS).

8.5 SINON

Branche alternative quand le QUAND arrive mais les SI ne sont pas satisfaits (cas simple sans multi-branches exclusives).

Exemple classique : « Détruire la clé USB » trop tôt → message d’avertissement.

8.6 TRANSITION (dans la situation)

Champ optionnel « Débloquer l’étage » : si cette situation réussit, elle peut aussi ouvrir un numéro d’étage.

Préférez souvent la transition d’étage (boîte 🔗) quand plusieurs situations doivent être réunies pour progresser.

8.7 Appliquer / Supprimer

  • Appliquer : enregistre les blocs dans l’aventure en mémoire, puis recompile les vues.
  • Supprimer la situation : retire définitivement la situation de l’étage (confirmez).

10. Transitions entre étages

Deux façons de progresser :

  1. Transition d’étage (recommandée pour les AND collectifs) — boîte 🔗 sous l’étage, ou bouton 🔗 Transition.
  2. Transition dans une situation — champ « Débloquer l’étage » dans l’éditeur de situation.

10.1 Mettre en place une transition d’étage

  1. Sélectionnez l’étage de départ (ex. étage 1).
  2. Cliquez 🔗 Transition ou la boîte pointillée sous l’étage.
  3. Ajoutez des conditions ET (ex. lettre consommée ET polaroid ET clé USB).
  4. Optionnel : message « DONC » (« Étage 2 — Rue de Paradis »).
  5. Appliquer la transition.

Résultat mental :

ÉTAGE 1 [A] [B] [C] (situations indépendantes) │ │ SI lettre ET polaroid ET clé USB ▼ 🔓 ÉTAGE 2

11. Branches alternatives (SI / SINON)

Cas Mira — Étage 8 « Détruire la clé USB » :

  • Situation A : appuie sur Détruire ET pas tout consommé → avertissement (pas de destruction).
  • Situation B : appuie sur Détruire ET tout consommé → destruction.

Comment le reproduire :

  1. Deux situations dans le même étage, même QUAND (« appuie sur Détruire »).
  2. Conditions complémentaires (l’une exige les médias consommés, l’autre l’inverse / le manque).
  3. Actions différentes.
  4. Validez : le Lab signale si deux situations partagent le même QUAND sans conditions distinctes (branche ambiguë).

12. Médias, items média, lieux, balises

12.1 Distinction cruciale

TermeSignificationExemple
MédiaLe contenuaudio_mira_01.mp3, photo, texte
Item médiaLe contenant immersifTalkie-walkie, Clé USB, Polaroid, Lettre

Skins d’items disponibles dans le catalogue : VHS, USB, Cassette, Dictaphone, Téléphone, Talkie, Radio, Lettre, Polaroid.

12.2 Lieux (zones)

Utilisés par « Le joueur est dans… ». Types supportés côté moteur : cercle GPS, arrondissement, polygone (selon définition).

Dans le testeur, choisir une zone place automatiquement le joueur au centre de cette zone.

12.3 Balises

QR ou NFC. Le QUAND « trouve une balise » + éventuellement la condition d’avoir déjà scanné.

13. Tester une situation

  1. Sélectionnez la situation.
  2. Onglet 🧪 Tester.
  3. Renseignez : position (zone), heure, date, médias déjà consommés, balises découvertes.
  4. Vérifiez l’identifiant d’événement (prérempli depuis le QUAND) et la valeur de code si besoin.
  5. Cliquez ▶ Simuler.

Résultat attendu (Mode Créateur) :

  • 🟢 SITUATION DÉCLENCHÉE + liste des actions humaines
  • ou ⚪️ non déclenchée / manquée — avec indices sur les conditions
Le test ouvre automatiquement les étages jusqu’à l’étage de la situation testée, pour que le « sas » d’étage ne bloque pas artificiellement votre essai unitaire.

14. Parcours joueur (session multi-étapes)

Contrairement au test unitaire, le parcours conserve l’état entre les étapes (comme un vrai run).

  1. Onglet Parcours.
  2. ▶ Démarrer le parcours — crée une session simulateur sur l’aventure compilée.
  3. Pour chaque étape : choisissez l’événement (consommer, se déplacer, scanner, code…), l’id, la zone, l’heure.
  4. Optionnel : cochez des médias déjà consommés avant l’étape.
  5. ▶ Étape suivante — lisez le journal humain et les étages ouverts.

La vue Parcours (centre) se met à jour avec les étages 🔵 ouverts.

15. Valider, compiler, alertes

15.1 Compiler

Traduit étages/situations → règles du Lantern Engine, rafraîchit Liste / Arbre / alertes. Faites-le après chaque série d’éditions importantes.

15.2 Valider

Contrôles créateur typiques :

AlerteSignificationQue faire
Étage inatteignableAucune transition n’y mèneAjouter unlockNext ou transition situation
Aucune situationÉtage videAjouter A, ou supprimer l’étage

16. Brouillons et sauvegarde

  • Sauver brouillon écrit un fichier dans le sandbox backend (backend/data/lantern-drafts/).
  • Les brouillons apparaissent à gauche ; cliquez pour recharger.
  • Ce n’est pas une publication joueur ni une persistance production.
  • Les fixtures (Mira) restent les modèles de référence ; vos brouillons sont vos variantes de travail.

17. Simulateur S1 (lien)

Le bouton Simulateur S1 ouvre l’UI technique historique :

  • Fixtures golden (Talkie Magellan, Appel 20h17, relatif)
  • Injection d’état, tick d’horloge, trace condition par condition

Utilisez S1 pour le debug moteur profond. Utilisez le Lab (onglets Tester / Parcours) pour le debug créateur au quotidien.

18. Tutoriel guidé — un bout de « Lanterne de Mira »

Objectif : comprendre le geste créateur sur un cas réel (déjà présent en fixture).

18.1 Explorer l’étage 0

  1. Chargez Lanterne de Mira.
  2. Dépliez l’étage 00 Déverrouillage.
  3. Situation A : QUAND consomme média imposé → ALORS débloque Bureau + message.
  4. Testez : cochez le média imposé, simulez → 🟢 déclenché.

18.2 Explorer l’étage 1 (parallélisme)

Trois situations indépendantes A/B/C. La transition 🔗 exige les trois consommations pour ouvrir l’étage 2. C’est le modèle « indices parallèles ».

18.3 Explorer l’étage 2 (géo + historique)

QUAND déplacement + SI dans Rue de Paradis + médias déjà consommés → note journal « ça sentait la PIZZA ».

Test : zone Rue de Paradis + médias cochés + simuler.

18.4 Explorer l’étage 4 (code)

QUAND entre le code PIZZA → débloque vidéo, lettre Mira, carte.

18.5 Explorer l’étage 8 (branches)

Deux situations, même bouton, conditions opposées. Testez les deux chemins.

19. Méthode de confection d’une Lanterne complète

Processus recommandé pour un concepteur seul :

  1. Pitch & découpage narratif — écrivez sur papier la liste des étages (0 = sas, 1 = indices, … fin = résolution).
  2. Inventaire matériel — médias, items (skins), lieux Paris, balises, boutons, codes, drapeaux d’état.
  3. Squelette Lab — nouvelle aventure → créer tous les étages vides avec titres.
  4. Situations cœur — une situation = une phrase « SI le joueur fait X, ALORS Y ».
  5. Transitions — pour chaque étage, définir clairement le DONC vers N+1 (AND / OR).
  6. Branches — identifier les forks (trop tôt / trop tard / déjà pris / choix moral).
  7. Temps & lieu — ajouter horaires, J+1, zones uniquement où le récit l’exige.
  8. Valider — zéro erreur rouge ; warnings compris et assumés.
  9. Tester unitairement chaque situation critique.
  10. Parcours bout-en-bout — session Parcours du début à la fin (au moins un happy path + une branche).
  11. Sauver brouillon — versionner mentalement (titre + date).
  12. Revue humaine — faire lire la vue Liste à quelqu’un qui ne connaît pas l’histoire : est-elle compréhensible ?
Critère de maîtrise. Vous maîtrisez le Lab quand vous pouvez créer un nouvel étage, y mettre deux situations concurrentes, une transition AND, une branche SINON, tester les deux chemins, et sauver un brouillon — sans ouvrir le Mode Développeur.

20. Erreurs fréquentes et bonnes pratiques

Étage suivant sans transitionParcours bloqué / alerteDéfinir 🔗 unlockNext

Confondre média et itemMauvais menuItem = contenant ; média = contenu

Bonnes pratiques

  • Nommez les situations comme des phrases narratives, pas des ids techniques.
  • Une situation = une responsabilité claire.
  • Préférez les transitions d’étage pour les AND collectifs.
  • Testez dès qu’une situation est « jouable », ne stockez pas 20 situations non testées.
  • Gardez Mira comme référence de complexité, pas comme logique magique (c’est de la donnée).

21. Ce que le Lab ne fait pas (encore)

Hors scope actuel (à ne pas chercher dans l’UI) :

  • GPS / NFC / QR réels sur téléphone
  • Test Terrain live à Paris
  • Publication joueur / persistance production
  • Éditeur graphique drag-and-drop avancé type « canvas infini »
  • Création visuelle complète du catalogue médias/zones depuis zéro (souvent préparé dans la définition / fixture)

Le Lab actuel = outil de création + validation + simulation au-dessus du moteur. Le terrain réel viendra ensuite.
